# Панель администратора

Встроенная панель доступна по `/admin/ui` (локально `http://localhost:8020/admin/ui`).
Она использует оформление и вход через IDU по аналогии с IDU_DVD; отдельная сборка frontend
не нужна. Корневой `/` по-прежнему открывает Swagger.

## Вход

Задайте в окружении или `.env`:

```dotenv
NG_AUTH_HELPER_URL=https://your-idu-auth-helper.example
NG_AUTH_HELPER_API_KEY=your-helper-api-key
NG_AUTH_HELPER_TIMEOUT=15
NG_ADMIN_ROLE=ADMIN
```

Используйте тот же auth helper, что и в IDU_DVD. URL — базовый адрес, без `/api/token`.
Проверка подписи и issuer использует существующие `NG_SERVICE_AUTH_SERVER_URL` и
`NG_SERVICE_AUTH_REALM`. Пользователь должен иметь realm role `ADMIN` (или роль из
`NG_ADMIN_ROLE`). Сервисные настройки `NG_SERVICE_AUTH_CLIENT_ID` и
`NG_SERVICE_AUTH_CLIENT_SECRET` по-прежнему нужны самому приложению.

Перезапустите приложение и войдите обычным логином и паролем IDU. Если helper не настроен,
форма покажет необходимые переменные. Пароль не сохраняется; токен находится в HttpOnly
cookie с `SameSite=Strict`, ограниченной путём `/admin/ui`. При HTTPS cookie имеет `Secure`.
При истечении сессии требуется повторный вход. При работе через reverse proxy настройте
доверенные proxy headers, чтобы приложение видело внешний HTTPS и Host.

Существующие REST/MCP маршруты продолжают требовать сервисный токен: админская cookie
не открывает к ним доступ. Все данные и операции панели защищены проверкой роли.

## Проверка документа

1. В разделе «Документы» найдите название или `doc_id` из IDU_DVD.
2. Откройте карточку: она показывает версию, корпус, пользовательский контекст, число пунктов
   и ограничений, состояние извлечения и ID пунктов с отмеченными ошибками.
3. Во вкладках «Пункты» и «Ограничения» доступны сохранённые тексты и нормы с исходными
   номерами пунктов. «Показать ещё» загружает следующие 50 записей.

| Статус | Значение |
|---|---|
| Завершено | `extraction_incomplete=false`: последний запуск завершил извлечение без отмеченных ошибок пунктов. Ноль ограничений допустим. |
| Не завершено | `extraction_incomplete=true`: обработка идёт, прервана или частична. Панель не различает эти случаи; обновите статус и проверьте логи. |
| Статус неизвестен | Пункты есть, но маркер извлечения отсутствует. Возможны ещё не обработанные или старые документы. Наличие норм само по себе не меняет этот статус. |
| Нет пунктов | Пункты не загружены; узел может быть только ссылкой из другого документа. |

Счётчики обзора относятся ко всему графу, включая документы-ссылки. Таблица показывает
документы в NormGraph, а не полный каталог IDU_DVD. Отсутствующий документ можно загрузить
через раздел «Обработка». Техническое завершение не гарантирует смысловую полноту норм.
Состояние Kafka в обзоре отражает включение потребителя, а не доставку конкретного события.

## Обработка

- «Загрузить и извлечь нормы» запускает синхронизацию по ID или точному названию. Название
  обрабатывает все найденные версии. Для пользовательского индекса укажите одновременно
  пользователя и сценарий. При синхронизации по ID уже сохранённый контекст сохраняется;
  попытка переназначить документ другому контексту отклоняется.
- Обычная синхронизация сохраняет идемпотентность: если документ не изменился, имеет нормы
  и не помечен незавершённым, дорогое извлечение пропускается.
- «Повторить извлечение» в карточке работает по сохранённым пунктам и дополняет результаты.
- Флаг «Пересоздать» вызывает `replace=true`: актуализирует структуру и заменяет ограничения
  после успешного извлечения. Интерфейс запрашивает подтверждение этой операции.

Операции с одним документом выполняются в рамках HTTP-запроса. Результат содержит
счётчики, предупреждения и ошибки по пунктам. История последней операции хранится только в
открытой вкладке; долговременная диагностика — в логах. Не запускайте пересекающиеся обработки
одного документа из разных вкладок, API или одновременно с автоматической синхронизацией.
Долгая обработка может превысить тайм-аут reverse proxy: после потери связи проверьте карточку
и логи перед повтором. Панель не считает сетевую ошибку доказательством остановки обработки.

### Перепарсить все нормы и планы

В разделе «Обработка» кнопка «Перепарсить все нормы и планы» после подтверждения запускает
фоновое пересоздание по сохранённым пунктам **всех загруженных документов**, включая пользовательские
документы. Документы-ссылки без пунктов не включаются. Файлы и структура в IDU_DVD не перепарсиваются.
Набор документов фиксируется при запуске; новые загрузки попадут в следующий запуск.

Документы обрабатываются последовательно с `replace=true`; нормы заменяются только при полном
извлечении без ошибок пунктов. Планы создаются обычным планировщиком, а экспертные планы с тем же
ID нормы сохраняют существующую защиту. Ошибки и предупреждения отмечаются отдельно, обработка
остальных документов продолжается. Панель показывает текущий документ, счётчики и первые 100 ошибок.

Вкладку можно закрыть: состояние доступно через API и снова появится при открытии панели.
Повторный запуск и одиночные операции из панели блокируются на время задания (`409`).
Задание и защита принадлежат одному процессу NormGraph: это не распределённая очередь.
Перезапуск сервиса прерывает выполнение и сбрасывает прогресс; автоматического возобновления нет.
Не совмещайте его с обработкой тех же документов через сервисный API или Kafka.

Раздел «Настройки» показывает выбранные параметры без секретов. Для изменения используйте
окружение и перезапуск. «Скачать логи» находится в разделе «Обработка».

## API панели

API `/admin/ui/api` принимает только админскую сессию. Изменяющие запросы и вход требуют
`X-NormGraph-Admin: 1` и проверяются на same-origin. Сервисные API остаются по прежним путям.

| Метод и путь относительно `/admin/ui/api` | Назначение |
|---|---|
| `GET /overview` | Счётчики графа и конфигурация синхронизации |
| `GET /documents?query=&state=&after=&limit=50` | Фильтрованный список документов |
| `GET /documents/{doc_id}` | Состояние документа |
| `GET /documents/{doc_id}/clauses` | Пункты документа |
| `GET /documents/{doc_id}/restrictions` | Ограничения документа |
| `POST /sync` | `{target, by: "id" или "name", user_id?, scenario_id?, replace: false}` |
| `POST /documents/{doc_id}/extract` | `{replace: false}` |
| `POST /reprocessing` | Фоновое пересоздание всего загруженного корпуса; `202`, без параметров |
| `GET /reprocessing` | Состояние последнего задания, прогресс и ошибки |
| `GET /settings` | Параметры без секретов |
| `GET /logs` | Скачать лог |

Списки документов, пунктов и ограничений используют курсор `after`, возвращают `items`, `has_more`, `next_after` и ограничены
100 элементами на запрос. Данные сортируются по ID; это не хронологический порядок пунктов.
